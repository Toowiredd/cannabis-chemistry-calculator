### Changed - 2026-07-25

- **`PresetActions` payload is now lossless** - `buildPresetPayload` writes per-field units (`weightUnit`, `tempOverrideUnit`, `bagWidthOverrideUnit`, `bagLengthOverrideUnit`, `volumeUnit`) and the full state (bag / strain / mode / concentrate / dose / advancedTools / label). The previous payload dropped per-field units (a 3.5 oz preset round-tripped as 3.5 g — 28× misread) and most of the wizard tabs' state (a "preset" wasn't a real snapshot). 211 lines of new test coverage in `PresetActions.test.tsx` for the round-trip.
- **`exportReport` uses per-field units across 6 sites** (`exportReport.ts:44-459`) - Every label + value uses `state.weightUnit` / `state.volumeUnit` / `decarb.tempOverrideUnit` for interpretation; display unit is applied via `convertWeight` / `cToF` at the report boundary. JSON `data` payload records both per-field and display units for downstream disambiguation. 178 lines of new test coverage in `exportReport.test.ts` for the per-field → display conversion (both directions).
- **`JournalTab.buildFormFromStore` uses per-field `volumeUnit`** - Was stamping the **display** `units.volumeUnit`, which meant a 100 mL entry shown in cup got a form pre-populated with `volumeUnit: 'cup'` and the entry card said "100 cup" (236× misread). Fixed at `JournalTab.tsx:132-150`.
- **`QuickBatchTab.handleLoadFromLastBatch` restores per-field `volumeUnit` + `strainId`** - Was setting `volumeUnit` to display only (engine reinterpreted 50 cup as 50 mL = 236× misread) and dropping `strainId` entirely. Fixed at `QuickBatchTab.tsx:346-372`.
- **`QuickBatchTab` Step 5 summary panel uses display unit** - Was hardcoding "g" for material weight, so an entry with `weightUnit='oz'` showed "0.12 g" (28× understatement). Now uses `convertWeight` at the panel boundary. Fixed at `QuickBatchTab.tsx:1053-1071`.
- **`JournalTab` entry card renders per-field `materialWeightUnit`** - `JournalEntry` interface extended with optional `materialWeightUnit` field; entry card at `JournalTab.tsx:738-761` converts at the display boundary (legacy entries fall back to 'g'). 273 lines of new test coverage in `JournalTab.test.tsx` (new file).
- **`KnowledgeTab` doneness curve honors `units.tempUnit`** - Slider tracks value in display unit, converts to °C at engine + store boundary, stamps `tempOverrideUnit: units.tempUnit` on apply; slider min/max + label follow the active unit (60–140 °C = 140–284 °F). 121 lines of new test coverage in `KnowledgeTab.test.tsx` (new file).
- **`AdvancedToolsTab` "Apply to Decarb Tab" preserves `decarb.weightUnit`** - Was applying the payload without writing the per-field unit, so a fresh store with `decarb.weightUnit='oz'` and a `weight` value typed in g would round-trip as oz and trigger the per-field refactor's 28.35× misinterpretation. Fixed.
- **`FirstTimerGuide` step 1 callout is method-agnostic** - The previous copy ("The one thing you cannot mess up: keep the oven at 235°F (113°C) and do not open the door during the first hour") was oven-specific but landed on every user regardless of method. Sous vide users read it as universal. Replaced with: "Every method has a critical detail that affects potency — the oven doesn't like an open door, sous vide doesn't like a bag above the water line. We'll show the right one when you pick your method in step 4. For now, just check what you have on hand." The per-method cards on step 4 already carry the method-specific caption.
- **`DecarbTab` thcPct gate removed** - The "We need an existing THC percentage" validation error was stricter than the engine (which handles 0 correctly per the dose-units refactor). Removed the gate; added `|| 0` to the engine call sites in both `DecarbTab.tsx` (concentrate + flower) and `MethodsTab.tsx` so THCA alone is enough to compute the theoretical max.
- **`QuickBatchTab` engine gate no longer requires `thcPct`** - The `hasDecarb` guard at `QuickBatchTab.tsx:118-119` was requiring `!isNaN(thc)`, so an empty `thcPct` (the common case for raw flower, which is THCA not pre-decarbed THC) made the engine return 0 and hid the "Total Infused THC" block on the Fat & Volume step. Now defaults to `parseFloat(decarb.thcPct) || 0` and only requires `weight > 0 && thca > 0`. Same shape fix in `DecarbTab.tsx:411-413` (flower) and `DecarbTab.tsx:378-380` (concentrate) and `MethodsTab.tsx:163-165`.
- **`FirstTimerGuide` "Use values from Decarb" shortcut honors `decarb.weightUnit`** - Was `parseFloat(decarbDefaults.weight)` with no unit conversion, so a user with `decarb.weightUnit='oz'` and `weight='0.25'` got `grams=0.25` (28× understatement of material). Now routes through `convertWeight(rawW, decarbDefaults.weightUnit, 'g')`. Fixed at `FirstTimerGuide.tsx:662-674`.
- **`FirstTimerGuide` "Open in Quick Batch" pre-fills the slices** - Was `setActiveTab('quickbatch') + dismissWizard()` only. Now writes the wizard's selections to the slices QuickBatch reads from: `grams → decarb.weight` ('g'), `thcaPct → decarb.thcaPct`, `matrix[0].method → decarb.presetId`, `fat → infusion.fatId`, `fatVolume → infusion.volume` ('mL'), `servingsPerFormat → dose.servings`. Fixed at `FirstTimerGuide.tsx:591-628`.
- **`FirstTimerGuide` matrix gate requires `theoretical > 0`** - The previous gate only checked the three picker arrays. If the user reached step 6 with `grams=undefined` or `thcaPct=undefined`, the engine produced 0 for every value and the matrix rendered 1-N rows of "0 mg / 0 mg / sub-microdose" — a real-looking recommendation that was actually "you didn't fill in your material yet". Added `theoretical <= 0` to the matrix gate. Fixed at `FirstTimerGuide.tsx:437-492`.
- **Focus ring is single-color (cyan)** - `globals.css:248-280` previously had two focus-ring sources: a global cyan 3px box-shadow on `:focus-visible` AND Tailwind utility classes (`focus-visible:ring-[var(--accent)]`) on individual buttons. Result: cyan on form controls, teal on buttons. The cyan rule was also forcing `border-radius: 0.375rem` on every focused button, which "snapped" corners on `rounded-lg` elements. Canonical color is now cyan. The 10 teal `ring-[var(--accent)]` class strings in `FirstTimerGuide.tsx` were stripped. A new regression test at `src/renderer/src/components/__tests__/focusRing.test.ts` recursively scans every `*.tsx` under `tabs/` and `components/` for the literal teal class string — will fail if anyone reintroduces it.
- **`engine.dosing.displayDoseLabel('low')` returns `'Low Tolerance'`** - Was `'Low'`, but `DoseTab`'s `DOSE_ZONES` table, the local `displayClassification` function, and the export report all used `'Low Tolerance'`. The journal entry's classification badge read "Low" while the Dose tab's classification card read "Low Tolerance" — same data, two different labels. Now consistent across the app.
- **`BagCalculator` + `DecarbHeatmap` per-field unit display** - These two display consumers were missed by the 2026-07-25 dose-units refactor: the engine boundary was patched but the display layer still read the old `units.*` token. `BagCalculator.tsx:400-408` now uses `convertWeight(value, decarb.weightUnit, units.weightUnit)` for the read-only Material Weight input. `DecarbHeatmap.tsx:56-85` now keys the F→C conversion on `decarb.tempOverrideUnit` (per-field) and the label on `units.tempUnit` (display). 122 → 215 component tests.
- **Experience topology audit baseline refreshed to 2026-07-25** - `docs/ui-ux-touchpoint-topology-2026-07-25.json` + `docs/ui-ux-touchpoint-report-2026-07-25.md` are the new human-readable + machine-verifiable baseline. The 2026-06-18 report is retained as a historical snapshot. New nodes: `ui_pwa_install`, `ui_inventory_section`, `ux_insufficient_material_gate`, `dx_per_field_units`, `dx_journal_source_provenance`, `dx_pwa_shim`, `dx_pwa_host`, `dx_pwa_validator`. Evidence types upgraded from `artifact` → `test` for every previously-failing critical node (`ui_first_timer_guide`, `ui_quick_batch`, `ui_decarb`, `ui_infusion`, `ui_dose`, `ui_journal`, `ui_dashboard`, `ui_knowledge`, `dx_store_contract`).
